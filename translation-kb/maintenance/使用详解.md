# 翻译、审校与维护详解

下列命令均从知识库顶层运行。[返回快速入门](../README.md)。

**新的翻译研究课题**　[从经文互文到译文取舍](../research/课题.md) 说明怎样分开检验出处、分句意义和中文语感，附 66 卷跨译本实验、语义辖域示例和第三方模型盲评办法。现有制包命令会在没有明确出处或长引命中时，用全经索引寻找平行段落，并列出需要复核的原文和经文用词。

**直接试用**　把 [Lori 第 133 篇翻译包](../examples/lori-133.md) 发给聊天模型，输入“请按本包翻译，逐段核对命中的用词，只交付中文定稿”。模型能同时看到英文、属灵军装的出处和同书用例。另有 [DYDI 第 003 篇翻译包](../examples/dydi-003.md)，其中保留了评阅者对“浇灌”的约定。

**已有初稿**　同一个模型可以接着做语义复核、中文朗读和定稿对照。 [六个真实片段的逐轮记录](../research/revision-cases.json) 保留了每处改动及理由。研究设计与验收结果见 [词语检索与多轮审校专项研究](../research/专项研究.md)。

## 为另一篇原文生成翻译包

在知识库顶层打开 PowerShell，使用 Python 3.9 或更新版本，SQLite 需支持 FTS5。脚本仅用标准库，制包和查经均可离线运行。手机或网页聊天模型只需收到生成的 Markdown。

```powershell
python lookup.py ../DYDI_Messages_Declaring_Your_Destiny.txt --book dydi --chapter 30 --out dydi-030.md
python lookup.py ../Daily_Words_The_Lords_Glory_with_Lori.txt --book lori --chapter 1 --out lori-001.md
```

独立的 UTF-8 原稿省略 `--chapter`。其他作品用 `--book other`，只检索通用条目。合订本按章标题提取正文，略过采集网址等元数据。每次选一个新输出文件名。上传生成的 Markdown 即可。

默认包包含精简指令和当前命中的提示。若首次委托重要篇章，或希望模型逐项遵守全部指南，在命令末加 `--full-guide`。[完整风格指南](../kb/style-guide.md) 说明语气与忠实度，单篇包另有按原文检出的用词。

## 从译前包到中文定稿

1. 用 `lookup.py` 选择原文，生成当篇翻译包。把这一个文件交给模型即可。
2. 模型依原文起草。同一条英文有几种圣经用法时，先看谁对谁说、动词支配什么，再取最贴切的中文。
3. 用 `check_terms.py` 核对这份包和初稿。已有语境依据的英文命中会逐段对照中文首选和允许的变体。将待核项交回译者，若别译更合原意，可以保留。使用 `revision.py` 的作业在语义轮和定稿轮自动得到这份清单。
4. 复核后将定稿并入合订本。检查命令只读文件。要接入批处理，加 `--json --strict` 可取得结构化报告，仍有待核项或段落无法对应时返回 2。若直接手动编辑合订本，仍需运行检查。

```powershell
python check_terms.py examples/lori-133.md 第133篇初稿.txt
python check_terms.py examples/lori-133.md ../Daily_Words_The_Lords_Glory_with_Lori_zh.txt
```

中文合订本会按包内篇号选篇，单篇中文稿可直接传入。检查会核对包内原文指纹，略过采集信息、篇后校注以及可识别的独立引文。分段数一致时按顺序对照；遇到分段数不一致时，报告英文定位并交译者确认。篇内另一段用了“军装”，不能抵消本段的“盔甲”。报告只核对词语线索，准确传达施受关系、句势和引文范围仍需逐句复读。

## 新约惯用语怎样进入翻译包

[知识库](../bible-style.sqlite3) 统一保存惯用词、出处、译法说明和本书用例。制包脚本用英文词形的首词索引筛选本篇候选，再检查完整短语、受词和语境。查单词时另有短语内部的词索引，例如查 `armor` 能找到 `whole armor of God`。模型收到的翻译包只列本篇相关提示。现有条目覆盖新约 27 卷，也保留诗篇、以赛亚书等更直接的出处。

| 待译原文 | 可用措辞 | 取舍依据 |
| --- | --- | --- |
| You wear My armor. | 你们穿戴我的军装。 | 弗 6:11 提供“军装”，本句只说 My。 |
| armored up in praise and worship | 以赞美和敬拜作军装 | 保留作者用什么作军装的比喻。 |
| the armor of light | 光明的兵器 | 罗 13:12 的完整搭配优先于单词 armor。 |
| armor and artillery | 装甲装备和火炮 | DYDI 第 152 篇谈军备援助。 |
| a sacred hiding place I have for you | 我为你们预备了一处神圣的藏身之处。 | 诗 32:7 提供“藏身之处”，本篇说神为人预备。 |

匹配先看本句。带 `~` 的少数线索可看同一段紧邻句首或句尾的十个词，例如 “You must put on your armor. You must fight in the Spirit.”。表中线索采用首字母大写的 My、Me、His、Your 时，会辨认该大小写。其余英文字母忽略大小写。排除项优先；有支持的短语优先于孤立词，同等证据优先呈现新约。在全经自动联想中，新约经节还获得有限的排序加权。原文明引的出处、诗篇的准确搭配和已评阅的作品约定各自保留。每包详列至多十二项，其他有语境依据的命中附在精简清单中；证据薄弱的词最多提示两项，供辨义。

**同书现译如何复用。** 同书用例按篇号、日期和来源网址配对，在可顺序对齐的英中段落内查找候选译词。查询按作品和义项从数据库取例。一个段落内重复出现只计一段，输出附最早例子的篇号、段号。同篇及已识别的同文重刊会从本篇提示中扣除。未带篇号且无法识别出处的片段仍使用经文规则。统计表示现行译稿中的同段用例，评阅者确认的用法单独保存在作品规则中。

```powershell
python -B -m kb.book_usage --examples armor --book dydi --chapter 152 --limit 1
python -B -m kb.book_usage
python -B -m kb.book_usage --check
```

第一条读取英中合订本，显示可对读的原段，也可查表外的新词。后两条在合订本或惯用词更新后重建、核对库内用例。日常制包直接读取随库分发的结果。

### 后续增补旧约惯用词

旧约首批已入库 58 个义项，出处覆盖全部 39 卷。其中诗篇 10 条、以赛亚书 6 条。每条都附英中文经节、触发表达与借用边界。例如《但以理书》10:6 的异象可提示“光明的铜”，工匠加工铜器的叙述另按原意判断。可从知识库顶层运行 `python -B scripture.py --word "bruised reed" --context` 查看“压伤的芦苇”及上下文。此批按代表性搭配选录，后续可依新稿实际漏检继续补词。

每批只整理本次增补的条目，义项使用独立 ID。同一个英文词可以有多个义项，分别记录出处、语境和译法。编辑时可用 UTF-8 TSV 交换数据，模板表头为 `id、triggers、preferred、variants、refs、cues、exclude、note`（实际用制表符分列）。多个值用 `|` 隔开，经节写作 `PSA.32.7`。需要参照现成数据时，可导出一份副本。

```powershell
python -B -m kb.term_store export 现有惯用词.tsv
python -B -m kb.term_store import 诗篇增补.tsv
python -B -m kb.term_store check
python -B -m kb.book_usage
```

导入时逐条对照库内 WEB 与和合本，经节或措辞核验失败会撤回整批。已有 ID 默认受保护，确要修订时使用 `python -B -m kb.term_store import 修订.tsv --update`。其他批次的条目保留。用例索引随词表版本核对，更新词表后运行最后一条命令即可恢复同书用例。日常使用 `lookup.py`、`scripture.py --word`、`check_terms.py` 时均无需导出词表。

### 三份文本在什么时候使用

日常制包、查词和逐轮审校从 `bible-style.sqlite3` 读取下表三类资料。维护者可以在文本中逐行校订、查看改动历史。给第三方程序分发运行包时可以省去这三个文本；给聊天模型翻译时仍只需发送单篇翻译包。

| 编辑底稿 | 库内表 | 用在何处 |
| --- | --- | --- |
| [scripture-terms.txt](sources/scripture-terms.txt) | `terms` | 制包时提供译名和搭配，审校时保护有经文根据的人名和地名。 |
| [word-senses.txt](sources/word-senses.txt) | `word_senses` | 按英文、上下文和排除词选用有据的经文措辞。 |
| [syntax-patterns.txt](sources/syntax-patterns.txt) | `syntax_patterns` | 按原文提示复核否定、条件、施受关系等，按编辑顺序选入翻译包。 |

改动这三份底稿后，在知识库顶层运行 `python -B -m maintenance.build_scripture --refresh-rules`，一次同步三表；任一底稿校验失败会撤回本次同步。运行 `python -B -m maintenance.validate` 可逐行核对交付库与底稿。新增旧约惯用词仍可走上面的分批导入流程。

## 条目的依据与边界

[SQLite 库](../bible-style.sqlite3) 内有 37 条风格与作品规则。16 条来自原指南，9 条来自首轮用户评阅，3 条来自用户复评（其中 1 条修订旧规则），其余 9 条来自新增 18 篇的英中审校。新条目标记为“编辑审校”，供后续译者核对语境，用户明确裁定的局部译法优先。[可读规则源](sources/rules.sql) 逐条列出英文触发表达、中文处理、作品、适用范围及出处。

## 离线经文与译名

数据库另收简体《新标点和合本》与 World English Bible 各 66 卷，以及 [186 条有经节出处的人名、地名、称号和常用搭配](sources/scripture-terms.txt)。这些属于底本参照。已评阅的作品约定继续优先，例如第 003 篇仍保留“我的荣耀”。[底本来源、逐卷条数、节号差异及文件校验值](经文底本与覆盖.md)

生成翻译包的命令同上。篇内标有 AMPC 或 NKJV 时，优先从独立出处行提取章节目，附和合本中文供核对。已有准确的和合本引文原样保留，来源标识照录。其他篇章优先查原文明引的章节目，最多显示两处，每处最多取所引范围前三节（底本合节完整显示）。没有可用出处时，脚本按段每四词取连续八个英文词，找到只匹配一节的片段时附一处双语候选。短引及改写可能漏检。直接查经支持罗马数字卷名如 I Corinthians、常见缩写如 Ps. 以及不连续节号如 Revelation 10:3, 5-7。

需要完整经文范围，或想查一个尚未建立映射的词，可直接运行下列命令。查词最多显示二十条，按所输入的原文片段匹配。

```powershell
python scripture.py --ref "诗篇 23:1-6"
python scripture.py --ref "Genesis 24:30"
python scripture.py --find "恩惠慈爱"
```

## 从词或短语查到一段经文

```powershell
python scripture.py --word mercy --collection psalms --context
python scripture.py --word "guard your heart" --collection paul --context
python scripture.py --word "保守" --collection wisdom
python scripture.py --word "mustard seed" --collection nt
```

`--word` 对已收英文词按译法分组计数，先列有新约出处的义项，附最多六处中英经文。“已核”表示词表有该处出处，“另见同词”只表示同节出现。检索报告写明所用词形和双语节界一致的计数范围。可用 `python scripture.py --word armor --collection nt --context` 比较弗 6 的“军装”、罗 13 的“光明的兵器”、林后 6 的“仁义的兵器”和路 11 的“盔甲兵器”。表外词沿用整组词、邻近共现和同节共现检索。中文可从和合本措辞反查。范围可选诗篇、智慧书、保罗十三封书信或整个新约，省略时查全经。`--context` 附同章前后各一节中文。需要更长上下文或节号有异时用 `--ref`。

查 *mercy* 时，诗篇 25:6 的恳求能看到“怜悯”，诗篇 23:6 的成对措辞能看到“恩惠慈爱”。查 *burden* 时，加拉太书 6:2 是彼此担当重担，6:5 是各人担当自己的担子。模型先看施事、动作和受词，再决定借哪几个字。

单篇翻译包自动执行这一步，通常无需手动查词。每篇最多附四处新增词语用例，其中全经自动找到的线索最多一处；另选最多三条句法提示。各条用例给出命中的英文、出处和中文。完整的 [词义与搭配表](sources/word-senses.txt) 和 [句法表](sources/syntax-patterns.txt) 也能直接阅读。

## 用同一模型续审

下面以已有英中合订本为例。单篇原稿和初稿可省略 `--chapter`。作业文件保存原稿副本、当前译文和各轮修改；可以中断后继续。

```powershell
python revision.py init lori129.db ../Daily_Words_The_Lords_Glory_with_Lori.txt ../Daily_Words_The_Lords_Glory_with_Lori_zh.txt --book lori --chapter 129
python revision.py next lori129.db --out 本轮.json
python revision.py apply lori129.db 模型答复.json
```

把“本轮.json”给同一个聊天模型，请它按其中格式返回 JSON。每次用一个新文件名导出下一轮。它可以提交零处修改。语义和朗读都查过，定稿对照再无可说明的改善，才标为“已收敛”。若定稿对照发现新问题，会再走一轮；最多六次。遇到改稿循环保留上次译文，达到上限仍有改动则记录待复核。

**审校已有校注的作品时，在初始化作业时带上原决定。** 可重复使用 `--note "本节已有的译法、出处和理由"`。例如《禧年书》23:25 的英文作 *a child of three weeks*，中文参考和本章上下文都支持“三周大的孩子”；第 47 章另有“七年期”的用法。模型每一遍都能看到这一层证据。若某个词已经由评阅者明确锁定，再用 `--protect "需要保留的原有措辞"`。

有兼容 Chat Completions 的模型端点时，下面的命令会连续执行。本例 URL 是本机服务的配置示例。模型名称填服务实际提供的标识；需要鉴权的服务可通过环境变量 `TRANSLATION_API_KEY` 提供密钥。配置的服务会收到本篇英中材料和本轮所需的知识库提示。[接口协议示例](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)

```powershell
$env:TRANSLATION_CHAT_URL = 'http://127.0.0.1:8080/v1/chat/completions'
$env:TRANSLATION_MODEL = '你的模型标识'
python revision.py run lori129.db --worker python model_worker.py
python revision.py export lori129.db --out 定稿.txt
python revision.py history lori129.db --out 审校记录.json
```

中断后可重用同一条 `run` 命令。已完成的轮次存于事务中。同一作业绑定首次自动运行的模型配置。格式错误或服务失败默认每轮尝试三次，耗尽后保留进度。每处改动要能在英文和当前中文中定位，保留原段落和已锁措辞。可在初始化时用 `--protect "准确的原有中文"` 追加锁定。对带出处的现成和合本整节，程序识别与底本汉字一致的连续引文；节号不全、改写或只引半节时，仍由模型结合上下文复核。

## 合订本的交付

批量重排中文合订本前先备份原稿。原文修正说明与译者待核实问题放在本篇文末、下一篇分隔线之前，便于逐篇复核。

## 验证与重建

```powershell
python -B -m maintenance.validate --books ..
python -B -m kb.wordstudy
```

第一条运行回归测试、在内存中重建并比对词义和搭配索引、核对两个底本和示例包，并统计两本文库的篇级触发情况。仅验证分发组件时省略 `--books ..`。第二条从已有 SQLite 经文和词义表重建词语索引。更换经文底本时按 [底本说明](经文底本与覆盖.md) 重建。

## 怎样吸收评语

逐条记录你确认的原句、上下文和译法。仅改动一处时，确认范围限于该处。可复用的意见补上适用条件，再找一个相似而应区别处理的例子验证。同步更新 SQL 和 SQLite 后，拿一篇未评过的原文生成新包，检查提示能否在合适的地方出现。整篇样本经你明确认可后再纳入范例。
