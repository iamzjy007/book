# 从经文互文到译文取舍：基督教文献翻译的可复核方法

## 研究问题

同一个模型使用相同的底本和推理预算，拿到本库后，能否在未见篇章中更常认出互文、保住作者有意改变的地方，同时写出读者愿意朗读的中文？二审、三审带来的净改善是否仍为正？本课题沿用项目的“信、达、雅”次序，以现代简体中文和《和合本》为首个目标。依据仍是原作、指定底本和评阅者明确表达的判断。用户确认的局部译法记录其上下文，迁移到新场景需要依据。

第一阶段已实现全经候选检索，并接入翻译包和 EPUB 核读。分句语义比较和盲排评测可在本目录独立运行。篇章级风格效果和跨语种迁移仍是待验证的假设。

## 哪些知识应当分开保存

| 对象 | 最小记录 | 如何复用 |
| --- | --- | --- |
| 文本证据 | 版本、作品、说话者、段句位置、连续原文、必要的前后句 | 查得到出处和边界。相同经节号下的不同版本也可能多一句或少一句 |
| 命题及辖域 | 事件、参与者与角色、事件之间的条件或引述关系、否定落点、语气强度、时间，分别附文字依据 | 被动句转主动句可以保住施受关系；祷告、推测、应许、引语保持各自身份 |
| 意象与修辞 | 所描写的对象、比喻物、对应属性、意象次序、复沓或转折、篇章作用 | 同一篇可以只借一词，也可以连续借四个并列分句。各分句分别决定 |
| 目标语表达 | 与同一命题相容的多个译法、语域、停顿、共享主语或中心词、经文出处 | “庄重”可以落实为动词直接、句式平衡、重音明确。一般叙事仍可朴素 |
| 编辑裁决 | 改前、改后、偏好理由、适用范围、证据等级、反例和版本 | 把“此处赞同”与“全书地名统一”分开；旧稿也作为可胜出的候选 |

不必让每个模型给每句话填五张表。普通段落给短提示；互文密集、神人称切换、疑难经文或两遍审校意见冲突时，再记录相应字段。已有 SQLite 管证据，Markdown 翻译包直接给第三方模型，首期没有新增模型权重或服务。

## 检索究竟证明什么

先将英文实词送入现有 FTS5 的 BM25 索引。常见宗教词会出现在许多节，罕见且共同出现的词对候选排序更有区分力。取前 24 节，再用允许插入和删除的局部序列对齐比较顺序。设待译和候选的实词为 x、y，本期递推为：

    H[i,j] = max(0, H[i-1,j-1] + s(xᵢ,yⱼ), H[i-1,j]-1, H[i,j-1]-1)

同一归一化词形得 3 分，替换扣 2 分。回溯最高点，记录对齐词、原文未对齐词、经文未对齐词。每段按最多 84 词、步长 60 词切窗。本期用至少四种独立词、局部得分至少 13 作展示门槛，每个包至多追加一处这一路的双语提示。分值是工程参数，没有概率含义。局部对齐适合拆开、插写的结构；比喻物完全换词或几处经文交织，仍可能漏掉。保留原有明确章节目、长引和词语级义项入口。[BM25](https://doi.org/10.1561/1500000019) · [Smith 与 Waterman 的局部对齐](https://pubmed.ncbi.nlm.nih.gov/7265238/)

《以诺三书》三十五章的实际底本未进入规则。通用检索在全经取回但十6，读者能同时看见原段未对齐的 *roaring* 和经文独有的 *beryl*。前者提醒译者听见额外的声势，后者提醒译者别把水苍玉添进译文。未对齐的 *polished brass* 与 *burnished bronze* 却可能表达同一意象。所以“未对齐”只触发核读，并不等同于“意义不同”。

## 语义和精义怎样约束借用

在给第三方模型的困难段落中，先依据待译原文回答三个问题：

1. 这是谁的话？作者自己断言，引述别人，还是记述人物尚未证实的信念？
2. 若用平实中文复述，谁对谁做了什么？哪些成分限制整句话，哪些只限制其中一个谓语？
3. 熟悉经文的读者容易顺势补上什么？原作者真正保留、改写或删去了什么？

随后以分句为单位决定沿用措辞、沿用句架、仅借局部，或自行翻译。所谓“精义”落实为该言语行为和该意象在**这篇作品**中的作用。譬如“我没有应许门会开”与“我应许门不会开”，即使词义、神学主题和大多数用字相同，也在作两件不同的事。作者有意保留模糊性时，把互斥读法及其依据并存。作者与通行释经意见有差异时，不把译者的神学解释塞进作者口中。[谓词与论元的语义角色标注](https://aclanthology.org/J05-1004/)

实验接口 `meaning.py` 比较原句与候选的命题记录，并逐项检查依据文字确实出现在相应文本。名为 `negated` 的标记从“应许”移到“开门”，即使两边都是否定句，也会报告两个变动。同一原文的两种中文见 `meaning-example.json`。当前语义记录由人或模型给出。程序能检查已写出的命题和证据；两次标注若共同漏掉同一层意思，结果仍可能虚假一致。正式盲测应让复核步骤只读译文、上下文和共享的概念表，先独立还原意思，再看原文。单一模型可分两次调用完成。

## 达与雅怎样比较

把初稿纳入候选集合。只有在关键意义相容的集合中，再比较汉语的自然度和体裁适切性。这相当于带约束的排序：一处施受颠倒不能用三处漂亮措辞抵消。“说话的轰鸣”准确指出了声势，但读者需先理解“说话”怎样修饰“轰鸣”；把声势放回描述声音的谓语，可继续比较两种朗读节奏。“各国各方之民”的收益也不在字数本身，而在两个修饰项能否自然地共用一个中心词。需要强调重复的诗歌，保留重复反而较好。

每轮仅接纳能指明改善、且经回读保住原义的修改，允许原稿胜出或两稿持平。评测记录新增严重语义错误、解决的旧错误、无益同义替换、读者偏好和跨轮复发。可把三轮后净改善定义为“有益改动数减有害改动数”，另单列严重错误，不能用净数抵消。对同一篇的相关句子按篇汇总；后续报告成对胜、平、负以及按篇重采样的不确定区间。一人评阅足以估计本项目偏好，不能从中推论所有读者都喜欢同一译法。[篇章上下文与翻译错误评价](https://aclanthology.org/2021.tacl-1.87/)

## 第一轮可复现实验

从不同于库内 WEB 的 KJV 数字版取 66 卷，每卷固定抽四节。先校验文件指纹，再对卷名和节号做映射；按基于卷章节的固定哈希排序取样，不按词汇相似度挑题。外部译本仅在测试时使用。264 节一律进入分母，包括短句。实现及快照 SHA-256 均在 `evaluate_parallel.py`。[KJV 测试数据](https://github.com/scrollmapper/bible_databases/blob/master/formats/json/KJV.json)

| 同一批 264 个查询 | 首位为采样节 | 首位为其他节 | 未展示 |
| --- | ---: | ---: | ---: |
| 原连续八词入口 | 76 | 1 | 187 |
| 八词优先，未命中再用通用对齐和展示门槛 | 151 | 2 | 111 |

消融检查：BM25 候选池前 24 中有 248 次包含目标；当作诊断、只取第一名且不设展示门槛时，BM25 首位正确 227 次，再对齐后为 231 次。可见本次主要收益来自扩大候选；对齐还提供了可核查的位置证据。生产门槛刻意舍弃许多首位正确却依据稀薄的短句，后续应按误借成本检验。该比较只评估出处检索通道，旧库的专名与词义提示原本另有用途。

两个指向其他节的结果都值得保留在报告中。代下六25找到王上八34，两处平行祷词略有出入；弥三12找到耶二十六18，后者实际引述弥迦。按预先指定的节号评分，两例均算误指。在翻译决策中它们可以提供措辞，却不足以替作者确定唯一出处。下一轮要同时标注“准确出处”和“可借用的平行处”，再比较误归出处和误借措辞的代价。

一个破坏性测试更重要。把以赛亚书式的“奔跑却不困倦”改写为“奔跑并且困倦”，保留前文。通用检索仍把赛四十31排第一。召回在这个例子上成功，照抄却会把作者的意思颠倒。三条无须引用的散文对照（磨铜、展览录音、果园）均未展示候选。八条新编的语义和语体最小对见 `contrasts.json`；它们有试验用答案，未获用户盲评。尚无第三方翻译质量胜率。

### 运行方法

在 `translation-kb` 目录运行，KJV 路径换成本地下载位置：

```powershell
python -X utf8 research/evaluate_parallel.py "D:\data\KJV.json"
python -X utf8 research/meaning.py research/meaning-example.json
python -X utf8 research/contrast_trial.py --seed 17
python -X utf8 validate.py --books ..
```

第三条命令输出顺序平衡、去掉编辑答案的 A/B 题。以同一随机种子加 `--answers 文件名` 可将一份完整选择与实验答案逐项核对，保留平局。两条语体题是编辑偏好，六条语义题是精确阅读测试，不能混成一个“准确率”。本页、题库和答案不随待译包发给受测模型。

## 下一阶段预先约定的验收

**串珠试用更新。** 独立实验入口现可用；下文“尚未导入”指正式制包入口。以同一份英文短文在本目录运行 `python -X utf8 beads.py 原文.txt --out 普通包.md` 和 `python -X utf8 beads.py 原文.txt --beads --out 串珠包.md`。两包仅在命中时相差一段锚词串珠。实测“锡安被耕如田”新增 Jer 26:18 的 Zion → Mic 3:12 关系；完整的《以诺三书》35:2 新增但10:6 的手臂、声音两组参照；删掉前半截的意象试句没有新增参照，普通耕地叙事也没有。以上只衡量提示变化。新稿以同一底稿分别审校，记录译文实际改动与胜平负，再决定是否默认启用。

本目录的 `tsk-kjv.tsv.gz` 为 [CrossReferences.org 制作的 KJV 词组串珠 TSV](https://github.com/CrossReferences-org/bible-cross-references/blob/main/tsv/crossreferences_kjv.tsv) 的无损压缩副本，依据 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 分发，原文 TSV 的 SHA-256 为 `d043b74921e2c2f61da7b00406bb559f9dbc6fc987e845a1c44bc187545e604b`。程序只筛选有关锚词；中文印本原有的串珠标记仍待独立核实。

### 两三个词触发的串珠实验

信望爱的中文查经界面可查看串珠，具体对应哪一版旧印本及其中文锚点仍待版本核实。CrossReferences.org 提供基于《Treasury of Scripture Knowledge》的词组级开放数据，含 KJV、BSB 等版本的锚词与分组目标区间，使用 CC BY 4.0。该来源可以检验“哪些词引向哪段经文”这个假设。引用数据时保留来源、版本、许可与本项目所作映射；中文锚词另在指定和合本上核读。[信望爱查经界面](https://a2z.fhl.net/ajax/) · [数据与格式](https://github.com/CrossReferences-org/bible-cross-references)

拟保留起始版本和章节、锚词原文、目标起讫节、中文对应短语及核验状态。查找时先让两三个词唤起多个候选，再看近邻语境；只沿有关锚词扩展一跳。编辑给出的主题联系可以帮助理解，不能单凭这条联系把现代文章改成经文措辞。验证时对同篇、同模型、同一提示预算开关串珠，记录新增有用联想、误借、漏掉作者变化，以及译文盲读偏好。以“弥迦原话和耶利米引述”作正对照，以普通耕地叙事作反对照。尚未导入这套外部数据。

1. **真正的第三方文献。** 与三十五章的开发样例隔开，预先选《多比传》c8BP、c8C4、c8BX、c8B1，《犹迪传》c8FP、c8E5、c8GT、c8F8，《所罗门智训》c8MU、c8JJ、c8JU、c8P2，《马加比一书》c990、c978、c960、c96S。单元由各卷 `SHA256("lit-v1/"+书号+"/"+单元号)` 升序取前四项。先登记标题或几乎无正文等无效单元及替补次序，再出任何译稿。这些书已有项目历史，不声称对模型训练语料或既有项目完全隔离。
2. **同一模型三种输入。** 固定底本、版本、生成预算和段落上下文。A 用现行风格指南，B 加旧检索材料，C 加新检索与分句取舍提示。保留输出、实际耗时、包长和调用次数。每种输入都允许三次审校；单独核验三轮是否胜过首轮。评阅时随机左右次序，隐藏条件名称；作者已确认的《以诺三书》改稿只作回归，不计入泛化收益。先用最强模型处理代表性难段与分歧处，无需让用户通评整批译稿。
3. **扩充底层表示。** 优先收集没有字面重合却确有互文、跨两节引用、同一段混合两处、同词却应当零推荐四类。对同一留出集比较当前路线、词义扩展和语义向量召回；固定候选数及给模型的字数。另测句法角色与辖域标注的独立质量。只有当更复杂方法能减少实际误译，并且单位成本值得时，才把它加入便携包。
4. **跨语种。** 第一项迁移先固定同一原文、同一命题证据，另取目标语言中有明确版本和使用传统的平行译本。验证该语言的敬称、韵律、引语、长短句偏好和当地读者是否认得那些经句。检索评测也需换源语分词和词形分析。现有算法和验证数据只支持英语检索与中文风格试验。

若更高的命中率伴随更多意义颠倒，停止提升自动借用程度；若增加提示使译者更拘谨、普通叙事更拗口，缩减提示。最终验收放在新篇章的译文、复审和人的阅读经验上。
