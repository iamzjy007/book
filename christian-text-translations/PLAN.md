# 翻译执行计划 v1

日期：2026-11-10 UTC。输入冻结提交号见 inventory/books.json。用户已授权每阶段提交并推送主分支，无需再次询问。不得强推。

## 一、范围与完整性门槛

110条先全部登记；其中51条仅为 fulltext_online 候选，另外59条不进入当前翻译队列。不能将“对应版本可直达”写成“51部原作完整”。每一候选都须读题页或版本说明、正文首尾、目录，并逐页或逐章检查正文连续性。作品集须拆作品；残篇、摘录、古书首尾残缺、现代重构本均单列，不因在线可读而升级为完整原作。保留原获取档案，不覆盖其继续任务。

- `needs_completeness_check`：候选入口，尚未完成本轮门槛。
- `ready`：所选版本全文可核，已登记语种、页码、章段、首尾和版本限制。
- `translating`：有已落盘单元。
- `translated_self_reviewed`：该版全部正文单元译毕，译者自身逐句复核；待核项仍须公开。
- `deferred_incomplete`：仅残篇／选译或古书有缺；等待另行确认翻译范围。
- `blocked_source`：访问、OCR、原语、版本或现代译本权利证据不足；记录精确下一步，继续其他可处理项。

## 二、选本与忠实性

1. 优先实际可核读的原语旧校本。不能因已有英译入口就跳过短篇原语检索。若只有古译，标明古译及原语关系；若用英、俄、法、德等译本，标明“据该译本转译”，列译者、版次及未核处。回译不是原文。
2. 冻结所选底本，记录URL、读取日期、页码/网页段号、扫描页图SHA-256；页面与OCR分开。OCR仅供定位，正文以页图为准。变更版本必须开修订记录，不静默覆盖已译单元。
3. 不补人物、教义、因果、经文，不以通顺为由增加解释。缺文用〔缺文〕；推测补足、采用校者猜改的文本，明确以〔拟补：……〕标出并列依据。方括号可能表示删文，须先查校本体例，不能一概视为缺损。
4. 按 GLOSSARY.md 处理术语；多义词先看语境。未定项逐条登记原词、位置、可选译法和理由。人名工作音译不冒称通行定译。
5. 保留自然段、章段号码和已有经文出处。印页换行和断词不当作自然段；跨页接续不重复。书末颂词如为底本正文须译出。校者经文参照另列“底本编者注”，不植入正文。可以逐字采用核实对应的和合本引文，不能用它填满原文只是化用的句子；不确定出处写待核。
6. 文风以自然准确的现代中文为基础，庄重、凝练；不得追求古雅而生硬，不模仿和合本具体句子。无法确定之处写“待核”，不猜。

## 三、排程与里程碑

M0：110条清查快照、51条候选队列、术语表、继续协议及校验工具，先提交到main。
M1：西里坦殉道者案录 → 居普良案录 → 游斯丁及同伴殉道案录。核旧校本全部篇幅，交付完整短篇，不把目录或摘要当正文。每完成一篇即可形成独立提交。
M2：塞巴斯特四十殉道者遗嘱 → 皮奥尼乌斯殉道记 → 修士天梯 → 论幸福生活 → 安布罗斯两篇。仍须逐一过完整性门槛；《修士天梯》须补PL扫描终段核验。
M3：按 queue.json 的剩余固定顺序，先原语文本，再可核旧外译。遇残缺、作品家族差异、OCR不可读或仅有现代译本者，具体记录并移交核源，不阻塞其他作品。
M4：长书按卷／篇逐批交付，每批约1500—3000外文词，允许依自然段及难度缩小；不设强迫赶工的完工日期。终期统一检查全书术语、交叉指引、段落连续性及总目录。

## 四、最小工作单元与落盘顺序

短篇用底本自带章段号；长书用稳定的“卷.章.段”号。无号自然段另设技术ID，明确非古代编号。单元以自然段或底本编号为边界，通常不超过400—600外文词，不拆句；超过者登记子单元和原父段号。每个单元保存定位、原文锚点、状态、译文哈希。

单元状态：`pending` → `draft` → `self_reviewed`。先选本和冻结完整单元表，再翻译。逐句核否定、条件、情态、说话人、重复、专名、缺文和术语；再通读中文。仅本人自校，不写成双人审校。

写盘顺序：先以同目录临时文件 + 原子替换写 translation.md，再写 review.md 和 source.json，最后更新 record.json。record的正文块哈希是确认单元已落盘的凭据。若正文已写而record未更新，续接时核其真实内容后登记；若record已写而正文丢失／哈希不符，停止该条进度推进，恢复或重新复核。两者都不因聊天说“完成”而自动确认。

## 五、每阶段验收与主分支提交

运行 `python christian-text-translations/scripts/check.py`。它核110条及51条候选、源记录哈希、单元唯一性和顺序、正文块哈希、全部正文有对应单元、完成状态与单元数一致、A/B/C/D资料齐全，以及派生队列和进度。结构校验不证明翻译学正确。

执行逐句自校后，更新REPORT、sessions和下一单元。先取远端main，确认无并发变化；有变化先合并保留远端内容，重校受影响文件。提交仅含本项目文件，按整篇或可独立阅读小批提交。优先用GitHub连接器push_files原子推送；若用git，只允许正常快进推送。推后核远端提交号及关键文件。网络失败保留本地成果并明记pending，下一次优先补推，不重复翻译。

阶段提交的SHA不写回同一提交内部，避免自引用；从Git历史或下一阶段日志读取。推送回执放 `/workspace/outputs/translation-delivery.json`（仓库外），副本便于交付，不能取代远端核验。
