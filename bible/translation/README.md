## 每次继续时

在仓库根目录执行：

```bash
python bible/translation/pipeline.py status
python bible/translation/pipeline.py next
```

1. 阅读本说明、根目录 `style-guide.md`、`scope.md`、`reference-map.json` 和 `glossary.json`。
2. 检查 `status` 是否有错误；程序核验原 EPUB 的 SHA-256，原件变更时会停止，须先核对变更，不能重建清单来掩盖差异。
3. 从 `next` 返回的第一项未完成单元开始。如返回 `scope_review`，先确认该边界作品是否纳入，再更新清单；程序不会自动越过它继续后面的书卷。提取源文，例如：

```bash
python bible/translation/pipeline.py source apocryphal-psalms c869
```

4. 阅读提取的全部正文，并核对对应的原 XHTML；遇到图像、表格、特殊排版、脚注或复合章节，先检查提取是否完整。`units` 是 EPUB 阅读顺序中的文件单元，不等同于章数。章节可能跨文件，不能按文件名猜测内容。
5. 在所提供的参考TXT中查找对应书卷和段落，记录文件名、位置、对应范围、差异。不要复制参考本中与当前英文无关的正典内容或编者扩写。
6. 建议每批一短卷或约3—6章，随章保存；长章可先保存草稿。无需等待整批完成才落盘。只要内容尚未完成双轮校核，`reviewed` 保持 `false`。
7. 单元译文保存到 `zh/<book_id>/<unit_id>.json`。可以使用脚本内的 `save(path, value)` 原子写入：先写临时文件再替换，避免中断破坏已有文件。
8. 译完后逐句对照、检查中文风格，将 `reviewed` 设为 `true`，再运行 `status`。结构检查不等于翻译质量审校，不能仅因程序通过就声明人工逐句复核完成。
9. 一本全部完成后，执行 `build <book_id>` 汇编 TXT。已确认书名可填入 `manifest.json` 的该卷 `title_zh` 字段，作为输出文件名。默认不覆盖其他书卷。

用户下次只需说：“继续 bible 目录的典外经书翻译，从已保存的断点开始。”

## 译文单元格式

```json
{
  "book_id": "apocryphal-psalms",
  "unit_id": "c869",
  "source_sha256": "从source输出复制，不自行猜测",
  "reviewed": false,
  "blocks": [{"id": "p0001", "zh": "对应源段的译文"}],
  "references": ["参考文件名、章节或行号、所借鉴范围及重要版本差异"],
  "notes": ["仅有必要时填写的原文修正说明或译者注"]
}
```

`blocks` 的编号、数量、顺序必须与源单元完全对应。节号由源文读取，汇编时自动输出，不把节号再次写入 `zh`。段落分组保留在提取结果的 `group` 中。原文有图像时，另须实际检查后明确记录处理方法，不能仅设置 `assets_reviewed` 就当作已译。

## 中断及恢复

- 完成状态根据译文文件、源文件指纹、段落编号和 `reviewed` 重建，`progress.json` 是可再生的进度表，不是唯一凭据。
- 已完整保存的合格译文自动跳过。缺失单元为 `pending`，已保存未复核为 `draft`，损坏或对不上原文的文件为 `invalid`；下一步总是最前面的未完成单元。
- 中断留下的 `.tmp` 文件不计为完成；不得用它覆盖已经通过校验的正式文件。
- 套餐额度无法由此脚本读取，也无法保证系统终止前有预警。逐单元保存能保住已经写入的工作；尚未保存的生成内容可能需要重做。
- 脚本不调用外部模型，不会自动消耗额度或在无人值守时继续翻译。下次由模型读取源文和状态后接续。
- 如需换环境，须先把本目录保存到 Git 或迁移整个目录。用户说“提交”时按此前约定提交、推送并合入主分支。

## 文件作用

- `manifest.json`：原件指纹、原书完整目录、范围判定和各文件阅读顺序。
- `scope.md`：可读范围清单；边界教父及殉道作品依用户暂缓要求记录，不悄悄遗漏或混入。
- `progress.json`：程序重建的当前进度。
- `reference-map.json`：参考资料指纹、已查到的对应关系和差异。
- `glossary.json`：本项目的译名与一致性约定。
- `zh/`：可独立恢复和校验的译文及必要说明。
- `output/`：分卷中文TXT成品。
- `pipeline.py`：只使用Python标准库的提取、检查、断点定位及汇编工具。
- `test_pipeline.py`：断点恢复与本批源文提取的回归检查。

## 无人值守续译队列（本轮新增）

用户已要求继续直到范围内全部译完。`work-queue.json` 将现有范围拆成220个任务，通常每批约5500英文词；极长单文件例外，需分块保存草稿。已有执行者在当前批次完成后持续领取下一批，直到队列无可领取任务。这个队列本身不是定时任务或外部模型服务。

```bash
python bible/translation/queue.py status
python bible/translation/queue.py claim 执行者名称
python bible/translation/assemble.py
python bible/translation/audit.py
```

- 领取由文件锁保护，同一任务不分给两名执行者。执行者必须只写自己获分配的book_id和units。
- 再次领取时会先返回本人尚未完成的任务；正式译文通过校验后，旧任务自动记为完成。
- 巨大单元可以在 `drafts/<book_id>/<unit_id>.json` 逐块累积，保留已译块ID、源指纹；全部完成后合成标准 `zh/` 文件并复核。草稿不计为完成。
- 会话/额度中断后，先核实旧执行者已经停止，才可执行 `python bible/translation/queue.py release all` 释放旧领取状态。该操作只释放任务归属，不删除任何译文或草稿。仍有执行者运行时不要释放，以免重复写入。
- 新会话先读 `PROGRESS.md` 和实时 `status`，再检查旧任务及草稿，继续最前面的缺口；不从头重译。
- `assemble.py` 只汇编全部单元通过校验的书卷，按原书顺序编号，生成分卷TXT及 `PROGRESS.md`。
- `audit.py` 输出异常短译或英文残留的线索，不能代替语义复核；零告警也不等于绝无误译。
- 边界的革利免书信及殉道文献已按用户暂缓教父作品的范围安排暂缓，见 `scope.md`，不会阻塞无人值守队列。
