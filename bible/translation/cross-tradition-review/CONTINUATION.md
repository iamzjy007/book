# 跨译本审校续接

## 先确认实际状态

先看 `REPORT.md`、`summary.json` 和 `coverage.json`，再读相应工作者记录。此目录的“重点审校完成”不等于全书全文校勘完成；旧 `zh/*/*.json` 的 `reviewed: true` 和旧队列的完成状态也不代表本轮重新核过全文。

检查 Git 当前分支、工作区和远端主分支，再检查实际代理／进程状态。日志中的 `claimed`、`in_progress` 或任务分配不能证明代理仍在运行。不得因为上一轮译文结构完整，就报告本轮研究已经穷尽或后台仍在工作。

本轮基线为 `coverage.json` 所列提交；逐书记录保存实际核对范围、取舍、来源和未决问题。缓存可重取，不能成为唯一证据。新增审校应新建有日期的记录，不覆盖这一轮的原始证据，也不能清空既有译稿来“重新开始”。

## 下一轮优先事项

1. **《雅煞珥书》继续逐章语义复核。** 第23章90节本轮已对两版扫描，最终修正6节。其余90章没有因此获得本轮全文校勘状态。若开展全卷新一轮审校，从第1章依次登记，遇已充分核过的部分可引用具体证据；不得只跑神名替换或字数检查。1987版仍为工作底本、1625版为对校本，已知缺叶和疑字须保留说明。
2. **有明确疑点的古语文本。** 亚他那修第57信“帕科米乌斯的主”的具体指代仍待希腊文本确认；奥利金致阿非利加努书的校勘符号说明也有未决细节。需落实到相应原文，不用熟悉神学措辞推定。
3. **保留歧义的启示文学。** 《童女启示录》28的时态与现稿“亘古蒙定”、西卜第三卷40行及第八卷部分难句、亚伯拉罕启示录14／20的产业句，见 `lori_a-apocalypses.json`。下一步须取得对应原语刊本或充分校记；不能因英文难通就宣布漏否定词。
4. **已登记的传本差异。** 巴录二书48:29的条件句、巴录三书的希腊／斯拉夫读法、雅尼与佯庇残篇等，见 `dydi_a-pseudepigrapha.json`。正文已明确修正的部分与尚未解决的异读分开处理，不拼合不同残篇成完整叙事。
5. **扩大长篇的实际核读范围。** 《犹太古史》《教会史》、大部书信集、伪经长篇等本轮主要是重点核读。按原书顺序读取未覆盖单元；参考记录中的 `remaining`、`unresolved`、`pending`、`next_unreviewed`、`next` 是具体入口。`coverage.json` 中 `partial` 的条目不能改成全文完成，除非已逐单元实际阅读并保存证据。

## 每批怎样保存

- 在对应 `zh/<book_id>/<unit_id>.json` 修改译文和简注；保持源指纹、块编号、顺序和原有范围。除明确有据的源文疑错外，版本差异只作必要说明。
- 改正文时，同时检查旧 `notes`、`references` 是否还声称沿用被改掉的读法。修订记录须保存最终措辞，不把试改后撤回的版本计入成果。
- 《雅煞珥书》仅修改 `hebrew-review/jasher/`，不把希伯来文修订混进旧英文源指纹体系。
- 对反义、否定、说话者、主宾、数字及古语疑错作独立复核。结构验证仅作完整性检查。
- 典外卷运行 `python bible/translation/assemble.py`；历史教父卷运行 `python bible/translation/history-patristics/assemble.py`；希伯来重审版运行 `python bible/translation/hebrew-review/jasher/manage.py`。复核修改后的正文和注释均已进入分卷TXT，检查差异后提交、推送主分支，并核实远端提交号。

中断时记录最后真正读到的单元／块、已保存的修改和未决证据。向用户说明真实中断原因；不得凭任务标签假称已恢复或仍在后台运行。
